# handoff-status

0.2.0，2026-10-20 建立，2026-11-01 更新。安装、发布和新会话核验见[根目录 README](../README.md)。

- 输入框上方的「待你处理」带。分类器拦下的命令和 Claude 用 `hand_off` 交来的步骤会进带子：命令项有 [复制] [我已运行] [授权你执行] [忽略]，授权项有 [授权] [先不做]。按钮以用户本人的名义回消息，按下即移出，同一项不会被回答两次；在聊天里授权后 Claude 重跑成功的命令也会自动移出。
- 输入框上方这块地方和别的 mod 共用：先取下层 mod 画的内容，再把自己的带叠在上面，不会遮住 context-bar-zh 这类条带（0.1.0 有内容时只画自己的，排在外层就会遮住下层）。叠法用 `hooks/bands.ts`，与 context-bar-zh 里的是同一份（取自 hamzafer/claude-code-mods，MIT，许可文本在文件头）；`<配置目录>/claude-code-mods/bands.json` 能排条带的上下顺序，本机没有这个文件，按默认顺序本带在上。
- 一轮进行中，转圈那一行显示工具次数、当前工具和整轮用时；当前工具跑满 10 秒后，再加上它自己跑了多久，如「当前 Bash：npm test（已 3 分 12 秒）」。会话有界面（`$.session.surfaces()` 非空）时每秒刷新；超过 60 秒多一个 [现在什么状态？]，旁路问一次模型，回答只显示在带子里，不进对话。
- 一轮结束后显示完成状态、用时、工具次数、模型 @ 网关、会话 id 前 8 位和工作目录，附 [现在什么状态？] [隐藏]；判为完成时多 [收尾 /neat-freak] [复盘 /retro]；以问题结尾且回答里有推荐时多一行 [按推荐执行] [先不做]。状态栏显示完成状态和模型。
- 因 API 出错结束的一轮，按引擎在 `StopFailure` 里给的错误类别写明原因：过载、限流、服务端出错、输出到了长度上限和未分类的错误多一个 [继续]，以用户名义发「继续」，按一次就收起；认证失败、账单或账户受限、请求被拒、找不到模型、用量到了上限（带重置时间）只写先做什么，不给 [继续]。
- 模型可调用的工具：`mcp__handoff-status__hand_off`、`mcp__handoff-status__close_handoff`。

## 已知限制

- 「在等你回答」「有未验证项」以及是否给 [按推荐执行]，都靠关键词判断，会漏判或误判。
- [现在什么状态？] 每按一次多一次模型请求；两个工具的说明让每个会话多占几百 token 上下文。
- headless `claude -p --output-format stream-json` 的输出里，每轮结束多一条插件的 `system/ui_status`（完成状态和模型）。没有界面时不每秒刷新，不出 `system/ui_invalidate`（2026-10-20 改动前实测一轮 77 秒有 76 条，改动后为 0）。
- 截至 2026-10-20 的核验：用户级安装后新开的 headless 会话加载了插件，两个工具都在，模型也答得出 `hand_off` 可用；改为从 `dist/handoff-status` 加载后，新 headless 会话的 `system/init` 也显示从那里加载。桌面端的真机证据都来自同一个早于安装就开着的桌面会话：「待你处理」带的显示（标题、命令、四个按钮）和 `close_handoff`，用的是安装前的开发副本；之后状态块的 [收尾 /neat-freak]、[复盘 /retro] 以用户名义发出了对应命令，两个命令项的 [授权你执行] 发出了授权消息，会话记录里这些消息的 `origin` 都是插件 handoff-status（授权消息另带 `asUser`），没分清加载的是开发副本还是安装副本。其余按钮、转圈行文字和它的每秒刷新、状态栏，以及 [复制] 失败时改用 `pwsh Set-Clipboard` 的回退，没有真机证据，只在 `claude plugin test` 的模拟里测过。
- 一轮还在进行时按下的回复按钮，消息先排队，会和之后排队的消息并成一条送达：2026-10-20 两个命令项的 [授权你执行] 就并成了一条用户消息。
- 0.2.0 截至 2026-11-01 的核验：16 项测试在 2.1.310 的测试套件上通过（新增叠带和 API 出错共 4 项，转圈行那项改为分别计时）；headless 新会话（2.1.310）从 `dist/handoff-status` 加载了 0.2.0，两个工具都在，一轮回答正常结束，状态栏输出「已完成 · claude-opus-5.5」。桌面端：会话从 `dist` 加载已安装的插件，证据是同一市场 context-bar-zh 的加载记录（根目录 README「发布」末条）；2026-11-01 12:45Z，一个这样加载的桌面会话里，状态块的 [收尾 /neat-freak] 以插件名义发出了命令，所以安装副本的状态块和这个按钮在桌面端能用，但 handoff-status 不记加载的版本，看不出那时是不是 0.2.0。叠带、[继续] 和单个工具计时在桌面端都没有真机证据。API 出错的分类依赖 `StopFailure` 的错误类别，走网关时准不准没验证；没收到 `StopFailure` 时按未分类处理，照样给 [继续]；用量上限靠英文原文里的「hit your … limit」识别。
