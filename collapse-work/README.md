# collapse-work

0.3.0，2026-11-03。第三方 mod 的本地改版，基于 FrogAi/Xenopus 的固定提交。来源、blob 校验和本地改动见 [SOURCE.md](SOURCE.md)；安装、发布和新会话核验见[根目录 README](../README.md)。

- 一轮结束后，把最终回答之前的过程收进一行「Worked for Xs ▸」。点一下展开，再点收起；最终回答保持原样。被中断的一轮不折叠，只在开头标「You stopped after Xs」。
- 终端收起工具行、结果、时长行和最终回答前的文字，thinking 里的说明不另收。
- 桌面端只收最终回答前的普通文字。工具组、单独的工具行、桌面 app 自带的卡片和 Opus 5.5 写进 thinking 的过程说明都照常显示，原因见「已知限制」。最终回答前没有可收的文字时，只显示一行不可点的「Worked for Xs」。这一行在桌面端上方不另加边距。
- 只认加载之后完成的轮次。每个会话的轮次表存在插件 store，保留最近 30 个会话；不联网、不调模型、不起进程。
- 文字一字不差重复的段落认不出属于哪一轮，照常显示；最终回答与别的段落重复的那一轮整轮不折叠。

## 已知限制

2026-11-03 在桌面 app 4.4212.0.0（自带 Claude Code 2.1.309）上核对。证据、截图对应的会话记录和桌面端代码位置见 `D:\agents\run-evidence\claude-mods\20261103-collapse-work-desktop-check\RESULT.md`。

- 过程说明收不了：模型在工具调用之间写得较长的说明，API 会压成摘要，存进带签名的 thinking 块，原文不作为普通文字保存。桌面端按签名认出这类块，当普通回复段落直接画，不经过引擎，mod 收不到请求。较短的说明仍存成普通文字，能收：2026-11-03 本仓库的一个会话里，一段 75 字的说明被收起，另一段较长的被压成 179 字的摘要，照常显示。压不压缩的界限没有查到。
- 藏掉的文字会留下一道空白：桌面端把 mod 接管的行换成一个高 0 的框，它仍占一个行间距（`--chat-item-gap`，约 10–16px）。`ui.render` 只能返回一棵树，没有「不画」的选项。
- 工具组标题收不了：桌面端把 mod 画的工具组追加在自己的组标题下面，不替换它。0.2.0 把组里的行和单独的工具行画成空，点开工具组看到的是空行，单独的工具行留空白；0.3.0 已撤掉。
- 0.2.0 的临时探针已删。它留在插件 store 的 `probe` 键，由 0.3.0 在会话加载时删掉；核对用的记录已存进上面的证据目录。
- 0.3.0 共 8 项测试（上游 4 项，本地桌面 4 项）在 2.1.316 的测试套件上全部通过，headless 新会话（2.1.316）从 `dist/collapse-work` 加载了 0.3.0；桌面端的实际效果还没真机核对。
