# context-bar-zh

0.1.5-zh.6，2026-11-01 加入，2026-11-03 改了桌面端的画法。第三方 mod 的本地简体中文改版，取自 hamzafer/claude-code-mods 固定提交里的 `context-bar` 0.1.5（MIT）；来源、blob 校验和本地改动见 [SOURCE.md](SOURCE.md)；安装、发布和新会话核验见[根目录 README](../README.md)。

- 桌面端（VS Code、手机同样）输入框上方默认两行。第一行左边「上下文 55%  251k / 456k」，右边「距自动压缩 172k」和 [展开]；离自动压缩点 ≥70% 这段字用主题的警示色、≥90% 用错误色，自动压缩关闭时显示「剩余 X」。第二行是铺满整行的细横条（`Svg` 矢量图）：「固定占用」（系统提示、工具、MCP、记忆文件、Skills 等每轮都带的内容）一段中性灰，「消息」一段主题橙，之后是剩余空间的浅轨道；自动压缩点画一条刻度（警示时随之变色），刻度之后的缓冲区更淡。条带不足 48 列时省掉 token 总数，不足 34 列时再省掉「距自动压缩」，标题行不折行。
- 桌面端展开后不加边框，横条下多出图例：「固定占用」及其下各类（系统提示、系统工具、MCP 工具……）的 token 数，再一行是消息、剩余空间、自动压缩缓冲的 token 数和占比，色块与横条各段一致；[展开] 换成 [收起]。
- 终端保持上游画法：第一行「已用 X / Y · Z 时自动压缩」和百分比徽标（≥70% 黄、≥90% 红）加 [展开]，第二行是按类别着色的字符横条；展开后是带框视图，多出标题「上下文」和每类的 token 数、占比。
- 展开只在当前会话有效，新会话一律折叠。
- 每轮结束、`/compact`、`/clear` 后刷新；用量由引擎在本地估算，不调 token 计数接口。`/context-bar` 显示或隐藏，这个选择跨会话保留。
- 每个界面第一次绘制时，把本会话加载的插件目录（`$.plugin.root`）、界面、会话 id 和时间追加进插件 store（`C:\Users\WINDOWS\.claude\plugins\store\context-bar-zh_claude-mods-*.json`）的 `loads`，保留最近 20 条，用来核对桌面会话读的是哪一份。记录里没有版本号，只有 zh.4 起的代码会写。
- 命令名 `/context-bar` 与上游版相同，两者同时启用会撞名、多画一条，所以上游 `context-bar@claude-code-mods` 已停用（`claude plugin enable context-bar@claude-code-mods` 可恢复）。

## 已知限制

- 桌面端把 `Svg` 画成 `<img>`，主题只经 `currentColor` 进到图里（桌面端把条带的文字色写到 SVG 根上）：固定占用、轨道、缓冲都用它加透明度，深浅主题都可读；消息橙和刻度的警示色是固定色值，不随主题变。
- 横条不再按类别上色：7 类固定占用加消息，按类别缺项的各种组合枚举全部 5040 种配色分配，没有一种能过 dataviz 校验脚本的正常视力 ΔE≥15 门槛（2026-11-03），所以横条只分「固定占用 / 消息」，类别明细放进展开图例。
- 截至 2026-11-03 的核验：0.1.5-zh.6 的 31 项测试在 2.1.310 的测试套件上通过。桌面端怎么画 `Box`、`Text`、`Svg` 读自桌面应用 4.4212 的 `ion-dist.asar`，按这些样式规则离线复刻渲染了 86、40、30 列的折叠和展开视图（浅、深色各一份），没有折行或溢出。真机桌面（浅色主题）上也核对过：一张是用户截图的展开视图（76%，警示色），一张是另一个桌面会话折叠视图的只读窗口截图（84%，错误色）。两张的各段颜色都和设计一致：固定占用是灰色，消息是橙色，轨道浅，缓冲区更淡，刻度随警示色或错误色变化，切缝处露出卡片底色。那个会话持续重绘时连拍了 12 帧（约 17 秒，每帧间隔约 1.5 秒），每帧都有横条，没有看到横条消失；不过比帧间隔更短的闪烁排除不了。深色主题只做了离线复刻，没在真机上看过。
- 截至 2026-11-01 的核验：0.1.5-zh.4 的 28 项测试（含按桌面界面挂载、加载记录各一项）在 2.1.310 的测试套件上通过；headless 新会话（2.1.310）从 `dist/context-bar-zh` 加载了 0.1.5-zh.4，没有加载已停用的上游 `context-bar`。加载记录：2026-11-01 有三个桌面会话（2.1.309）写进了 `context-bar-zh_claude-mods-8ab2ddccf0ea.json`，`$.plugin.root` 都是 `dist\context-bar-zh`；三个会话都在发布前就开着，见根目录 README「发布」末条。桌面端（桌面 Code 标签页自带 2.1.309）：0.1.5-zh.1 的用户截图里，展开视图能显示，说明 [展开] 能用；折叠时横条折成了两行。按 2.1.309 的声明，桌面按代码字体的字宽算 `bodyColumns`，横条却是用界面字体画的，`█─░` 在界面字体里更宽。0.1.5-zh.3 改用 `mono` 画横条后，用户在新开的桌面会话里确认用量行和横条显示正常；zh.3 起的展开视图还没在桌面上看过。原样上游的两条条带顺序测试在 Windows 上必失败，是测试里的路径问题，已在本版测试修掉，见 SOURCE.md。改版固定在上游那次提交，不会自动跟随上游；上游更新要手工合并。
